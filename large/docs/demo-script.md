모든 데이터는 가상입니다(300명·25팀, 이메일 `example.com`). 아래 수치는 **실측이라고 적힌 것만** 실제로 잰 값입니다.

## ★ 발표 당일 순서

명단을 처음부터 올리는 장면과 정산 보고서 장면은 **DB 를 나눠** 씁니다. 시드 DB(가짜 300명, E260001~)에 명단을 올리면 ID·Slack ID 가 겹쳐 섞이기 때문입니다.
두 스크립트 모두 저장소 어디서 실행해도 되고, 시작할 때 **지금 어떤 DB(live/seed)로 켜졌는지와 NOTIFY_MODE·LLM_MODE** 를 출력합니다. 같은 포트에 서버가 켜져 있거나, `--reset` 으로 지울 DB 를 다른 서버가 쓰고 있으면 실행을 멈춥니다(켜진 서버 밑에서 DB 가 지워지지 않게).

## 0. 준비 (발표 10분 전)

```bash
# 저장소 루트. 처음 한 번: python3.11 -m venv .venv && .venv/bin/pip install -r hub/requirements.txt
(cd large/frontend && npm ci && npm run build)
(cd large/backend && ../../.venv/bin/python -m app.seed --reset)      # 시연 데이터 초기화(오늘 기준 날짜)
.venv/bin/python -m hub                                              # http://127.0.0.1:8787
```

- **초기화는 시연용 DB 에만 됩니다.** 시드가 만든 DB 에는 `db_meta.purpose='demo-seed'` 표시가 있고, 이 표시가 없는 DB(운영 데이터일 수 있음)나 `APP_MODE=production` 에서는 `--reset` 이 거부됩니다. 대상 파일: `large/backend/var/chongmu.db`.
- 같은 날짜 조건으로 똑같이 만들려면 `--base-date 2026-10-15` 처럼 기준일을 고정합니다(같은 시드·기준일 → 같은 사람·같은 거래).
- 실제 Gemini 로 시연하려면 `large/backend/.env` 에 `LLM_MODE=gemini`, `GEMINI_API_KEY=…` (Git 제외 파일). 키가 없거나 호출이 실패하면 규칙 기반으로 대체되고 **말풍선에 "⚠ LLM 실패 → 규칙 기반 대체"** 가 뜹니다. 화면 위 띠의 `LLM Gemini / LLM 모의(규칙)` 로 현재 모드를 확인하세요.
- 발표 등장인물(시드 고정, 초기화 출력에도 나옴): **T10 참가자**(주 장면), T10 담당자, T16·T19 담당자(입금자 불명), T13 담당자(중복 입금). 대모임 화면 상단 **역할 전환**(`/large/roles`)의 '발표 등장인물' 버튼으로 바로 들어갈 수 있습니다.
- 백업: 브라우저 탭을 미리 열어 둡니다 — ① 총무(PC) ② 참가자(휴대폰 크기 창, 개발용 수신함의 초대 링크로 진입).

### 보조 사례
**A. 입금자 불명 'ㅎㅂ' 210,000원** — 확인 과제 탭 또는 T16 담당자 화면
- 정산 처리(규칙 R4)는 금액이 같은 미납 팀(T16·T19 등)을 **참고 후보로만** 기록하고 각 담당자에게 "우리 팀 입금인가요?"를 묻습니다. 금액이 같다는 이유로 배정하지 않습니다.
- 한 팀만 '네'면 배정 *제안*, 모두 '아니요'나 여러 팀 '네'면 총무 이관. → 사람: 담당자 답변·총무 확정 / 코드: 후보 계산·재검토. **LLM 은 이 판단에 쓰이지 않습니다.**

**B. 개인·팀 중복 입금(T13)** — T13 담당자 화면
- 장현우님 개인 20,000원 + 팀 일괄 입금 → 수납이 회비보다 20,000원 많음 → "팀 입금에 포함됐나요?" 확인 과제. '네' → 중복 납부로 정산 잔액에 추가 환불로 남음.

**C. 분할 입금(T22)** — 입금 대조 탭: 'T22 1차'·'T22 2차' 두 거래가 같은 팀으로 각각 제안됨.

### 마무리 멘트용 정리
- **LLM 이 하는 일**: 참가자·담당자 말 해석, 어떤 기록을 볼지(도구) 선택, 정보가 모자라면 질문, 변경 도구 선택.
- **코드가 하는 일**: 금액·환불 규칙 계산, 본인/자기 팀 권한, '네/아니요' 판정과 실제 기록, 중복 배정 방지, 입금 대조·확인 과제(규칙 R1~R6).
- **사람이 하는 일(HITL)**: 마감 후 변경 승인, 배정 확정, 이관 과제 처리, 정산 확정, 송금 결과 기록.
