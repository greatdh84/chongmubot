## 2. 과제물 Mindset ✅🎙️
- 내 업무, 생활 속에서 **어떤 일을 할 수 있을까?**
- **어떤 기능으로 무엇을** 만들 수 있을까?
- **AI Agent 활용을 중심으로**, AI 에이전트를 정의해서 만들 것
- **실제로 쓸 수 있는 AI tool**을 만드는 것이 목표

### 🎙️ 강사님이 강조한 태도
- **코딩 스킬보다 아이디어·발상이 훨씬 중요하다.** 오늘 배운 새 마인드를 장착한 상태에서 무엇을 만들지 발상할 것
- **기존 소프트웨어의 한계·상상의 제약을 버려라.** 하드웨어 제어(예: 조명 켜고 끄기)까지 만들 수 있음. "이런 걸 만들면 편리하겠다"는 아이디어를 과감하게
- **끝까지 못 만들어도 괜찮다. 그대로 발표하라.** "왜 안 됐는지를 공유하는 것은 엄청난 지식"
- 혼자 하다 옆 사람 도움을 받아도 되고, Slack으로 물어봐도 됨. 두려워하지 말고 Cursor 등 에이전틱 코딩으로 **직접** 만들어볼 것

1. **AI Agent를 반드시 적용한** 업무용(또는 생활 속 일의) 앱
2. 그 일의 **워크플로를 flowchart로 정리**
3. 발표 때 **AI 적용 전 워크플로와 적용 후 워크플로를 함께 보여주기**

## 4. 요구사항별 준비 방법 💡 (강의 내용 연결)

### 4-1. 주제 고르기
**① 자동화 대상 업무 4조건**(강의 2-6) 중 해당되는 게 있는지
- 반복적이고 시간이 많이 드는 일
- 사람이 실수하기 쉬운 데이터 집약적 일
- 예측 가능한 질문과 답변으로 구성된 일
- 프로세스가 명확하고 **표준화할 수 있는** 일

**② Four Gets**(강의 2-10)로 검증
- **Get Them** — 사용자가 누구인지 한 문장으로 말할 수 있는가? (AI로 타깃 페르소나를 정의해봐도 좋음)
- **Get Simple** — 사용자가 할 일이 많아야 두 가지인가? (강사님 여행 경비 앱: "사진 한 장이면 끝")
- **Get Me** — 사용자에게 딱 맞춘 결과를 주는가?
- **Got It!** — 결과를 보면 "오, 이거야!" 하고 다시 쓰고 싶은가?

**③ 강의 속 참고 사례**
- 청구서 3종 일괄 PDF 발행 앱, 영수증 사진 기반 여행 경비 실시간 정산 앱
- 도매 상품 사진 → 설명 자동 생성(남대문시장 사례)
- 경영진 주간 대시보드 자동화(MCP)
- 다국어 챗봇 + 뒤에 에이전트 배치(언어 감지 → 의도 분석 → 답변 → 미해결 보고)
- YouTube 시나리오 생성(CrewAI 3인 에이전트)

**④ 발상 팁** 🎙️: 잠시 멈추고 생각하기, "사람이 무엇을 불편해하고 좋아할까"에 집중, 내 **전문 도메인**과 결합

### 4-2. 워크플로 정의 (전/후 비교) — 발표의 핵심
**Step 1. AI 적용 전(As-Is)** — 현재 업무를 단위별로 쪼개 순서대로 적기(누가 / 무엇을 / 어떤 도구로 / 얼마나 걸리는지) → **draw.io**로 flowchart 🎙️(강사님 추천 도구)

**Step 2. 문제 지점 표시** — 쪼개면 보이는 **병목, 중복작업, 비효율**을 flowchart 위에 표시

**Step 3. AI 적용 후(To-Be)**
- 어느 단계를 AI Agent가 맡는지 — 예측 / 생성 / **실행**까지 맡기는지 구분 (강의: AI는 이제 execution까지 함)
- **HITL 지점 명시**: 사람이 어느 시점에 개입하는지 (결정, 검증, 승인 등) — 강사님 표현으로 "핵심 중의 핵심"

**Step 4. 전/후 비교표**

| 비교 항목 | AI 적용 전 | AI 적용 후 |
|---|---|---|
| 단계 수 | | |
| 소요 시간 | | |
| 사람이 하는 일 | | |
| 오류 가능 지점 | | |
| 사람의 개입 지점(HITL) | | |

> 수치는 직접 재본 값이나 근거 있는 추정치로, 추정이면 "추정"이라고 표시하는 게 안전합니다.

### 4-3. AI Agent 앱 구현 — 강의 도구 매핑

| 필요한 것 | 강의에서 배운 방법 |
|---|---|
| Agent 정의 | Persona(`role`·`goal`·`backstory`) + Task(`description`·`expected_output`) |
| 시작 방법 | 🎙️ 처음엔 Cursor에 **"AI 에이전트로 정의해주세요"** (프레임워크 없이 직접 코드) |
| 멀티 에이전트 | CrewAI: Tools → Agent → Task → Crew → `kickoff()` (순서/동시 실행 구분) |
| 외부 데이터·앱 연결 | MCP — **공식 MCP만**, 최소 권한, 자동 업데이트 금지 |
| 컨텍스트 | `.cursorrules`, `Initial.md`/PRD, 필요한 시점에 필요한 것만(토큰), markdown·XML·JSON |
| 정확한 요청 | Context Word (CRUD, bfcache, Lighthouse …) |
| 글로벌화 | 🎙️ **"과제할 때도 해보세요" — i18n(+l10n) 적용** |
| 품질 | 테스트 데이터 생성, CWE/NVD 보안, Lighthouse, WCAG AA, README |
| 버전 관리·배포 | commit 자주 → GitHub push → Render 등에 deploy (터미널 명령은 토큰 비용 없음) |

### 4-4. 2인 협업 방식
- GitHub repo 하나를 공유하고 각자 branch에서 작업 후 merge (C에서 필수는 아니지만 충돌 관리에 유리)
- 역할 분담 예시
  - A: As-Is/To-Be 워크플로 조사·flowchart, Agent persona·task 설계, 발표 스토리
  - B: Cursor로 구현, MCP/API 연결, 배포
  - 공통: 테스트, 데모 시나리오, 발표
- 발표는 **두 사람이 함께 나와야** 하므로 파트를 나눌 것 (예: 한 명은 문제·워크플로 전/후, 한 명은 앱 구조·데모)

## 5. 발표 구성 예시 💡
1. **문제 정의** — 어떤 일, 누구의 일인가 (Get Them)
2. **AI 적용 전 워크플로** — flowchart + 병목·중복·비효율
3. **AI 적용 후 워크플로** — 에이전트가 맡는 부분, HITL 지점
4. **전/후 비교표**
5. **앱 구조** — 에이전트 정의(role/goal/task), 사용한 도구·MCP
6. **라이브 데모** (녹화본 백업)
7. **한계와 개선 방향** — 🎙️ 못 끝낸 부분이 있으면 "왜 안 됐는지"도 그대로 공유
