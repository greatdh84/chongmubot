## 1. 새 컴퓨터에서 시작하기

```bash
git clone https://github.com/greatdh84/chongmubot.git
cd chongmubot
git switch feat/slack
python3 -m venv app/.venv
app/.venv/bin/pip install slack_bolt
```

`.env` 는 GitHub 에 없다. **기존 컴퓨터의 `.env` 를 직접 옮기거나**(메신저·메일로 보내지 말 것), 아래 값을 각 콘솔에서 다시 복사해 만든다. 형식은 `.env.example` 참고.

| 항목 | 어디서 | 비고 |
|---|---|---|
| `SLACK_BOT_TOKEN` (`xoxb-`) | api.slack.com/apps → 총무봇 → Install App | 수업 워크스페이스에 설치돼 있음 |
| `SLACK_APP_TOKEN` (`xapp-`) | 총무봇 → Basic Information → App-Level Tokens | scope `connections:write`. 참석 조사 [응답하기] 버튼에 필요 |
| `SLACK_OWNER_USER_ID` (`U…`) | Slack 내 프로필 → ⋮ → 멤버 ID 복사 | 총무 본인 |
| `LLM_API_KEY` (`sk-ant-`) | console.anthropic.com → API Keys | 모델 `claude-haiku-5-5` |
| `KAKAO_REST_API_KEY` | developers.kakao.com → 앱(도총과채총) → 앱 키 | 카카오맵 사용 설정 ON 필요 |
| `KAKAO_JS_KEY` | 같은 곳, JavaScript 키 | JavaScript SDK 도메인에 `http://127.0.0.1:8787`, `http://localhost:8787` 등록돼 있음 |

실행:

```bash
app/.venv/bin/python app/server.py
```

브라우저로 **http://127.0.0.1:8787** 을 연다 (파일로 열면 Slack·검색·지도·사진 읽기가 안 됨 → 데모 모드).
macOS python.org 파이썬은 인증서 문제가 있어 서버가 `/etc/ssl/cert.pem` 을 자동으로 쓴다. 다른 OS면 확인 필요.

### Slack 앱(총무봇) 현재 설정
- Bot scopes: `users:read` `channels:read` `channels:manage` `chat:write` `chat:write.customize` `im:write` `im:history` `reactions:read` `reactions:write`
- Socket Mode ON, Interactivity ON, Event Subscriptions ON (`message.im`), App Home 메시지 탭 ON
- 앱 설정 원본: `app/slack-manifest.json` (봇 표시 이름은 영문 `chongmubot` 이어야 함)
- ⚠️ **수업 워크스페이스(약 380명)에 연결돼 있다.** 시작하기를 누르면 실제 채널이 생기고 초대 알림이 간다. 테스트는 본인(·채총)만 초대, 채널 이름은 `chongmu-test2` 처럼.

## 2. 구조

```
app/server.py      로컬 서버 (표준 라이브러리 + slack_bolt). 데모 화면도 같이 제공
app/data/          참석 조사 응답 저장 (survey.json, git 제외)
app/slack-manifest.json
demo/index.html    화면 전체 (한 파일). 상태는 브라우저 localStorage `chongmubot-demo-v3`
```

### 서버 API (`app/server.py` 맨 위 주석에 전체 목록)
- Slack: 멤버 목록, 채널 생성·초대, 발송(`/api/slack/send`), 이모지 투표 생성·집계, 스레드 댓글, 참석 조사 버튼, 모임 취소 안내
- 발송은 Claude 가 성격대로 **처음부터 짧은 메시지 1~3개**로 써서 1~2.5초 간격으로 나눠 보냄 (`compose`). 금액·확정 공지는 `raw:true` 로 그대로 보냄
- 카카오: 장소 추천(`/api/places/recommend`, 카카오 검색 → Claude 가 고름), 검색 자동완성, 지도 클릭 근처 음식점
- Claude 사진 읽기: 입금 문자·캡처(`/api/pay/parse`), 영수증(`/api/receipt/parse`)
- Socket Mode(`start_socket`): [📝 응답하기] 버튼 → 입력창 → `app/data/survey.json` 저장 → 고맙다는 DM

### 화면 (`demo/index.html`) — 회식 관련 주요 함수
| 영역 | 함수 |
|---|---|
| 설정 화면 순서 | `setupSections()` → 회식: 슬랙 · `dinnerPlan` · 조사 항목 · `dinnerFee` · 성격·전략 · 메시지 |
| 회식 상태 기본값 | `defaultDinner()`, `defaultVote()` (`S.dinner`, `S.vote`, `S.survey`, `S.settle`, `S.phase`) |
| 대시보드 | `renderDinnerDash()` · 단계 `S.phase`: `plan` → `survey` → `event` → `settle` |
| 1단계 날짜·장소 | `pollCard`, `pollCloseModal`, `dinnerKickoff`, `VOTES`, `tallyOf` |
| 2단계 참석 조사 | `surveyCard`, `surveyPull`(5초마다 응답 읽기), `surveyQuestions` |
| 3단계 모임 | `eventCard`, 시트 칸 클릭 `cellEdit` |

## 3. 회식 흐름 (현재 동작)

0. **설정**: 모임 종류 회식 선택 → 날짜·장소를 각각 "총무가 정하기 / 투표로 정하기", 카카오 AI 추천·검색·지도에서 후보 고르기, 조사 항목(기본: 이름·참석·회비·1차·2차·도착 시간·음주 여부), 회비·정산(후정산 기본, 기본회비 옵션·금액, 1·2차 따로, 술 안 마신 사람 할인, 계좌)
1. **시작(HITL 1)** → 채널 생성·초대 → 일정 공지 → 투표 항목만 이모지 투표 → 마감하고 확정(HITL) → 확정 공지(+기본회비 안내) (HITL 2). 날짜·장소 둘 다 총무가 정했으면 투표 건너뜀
2. **참석 조사**: [응답하기] 버튼 메시지(마감 기본: 모임 3시간 전) → 응답이 시트에 반영 → 조사 마감(HITL, 무응답 불참 처리 선택) → 최종 인원 공지
3. **모임 당일**: 시트 칸을 눌러 수정 → 모임 종료(HITL)
4. **정산**: 1·2차 금액 입력 또는 영수증 사진 → 자동 계산 → 정산표 확정(HITL) → **각자 자기 금액만 DM** + 단체방엔 안내만 → 입금 확인(회비 열) → 환급 "보냈어요" → 정산 완료 공지(HITL)

## 4. 정해 둔 규칙 (사용자 결정)

- 자동 독촉은 **단체방에만**, 이름 없이 인원만 ("아직 3명이 …"). 개인 DM 은 **총무가 대시보드에서 정할 때만** (강도·빈도 선택)
- 정산 금액은 **개인 DM 으로만**. 단체방에 금액표 올리지 않음
- 모임 중단은 취소 안내만 남기고 **채널 보관(archive) 하지 않음**
- 계좌번호·실명 같은 개인정보를 **코드 기본값으로 넣지 않음** (GitHub Pages 공개)
- 장소 메모는 Claude 문장 대신 **카카오 업종 분류**만 (메뉴 정보는 카카오 API 에 없음. 총무가 직접 적을 수 있음)
- 1인 예산·가격 추정 칸은 뺌
- 독촉 간격 프리셋 12시간·1시간·10분·🔥15초, 개인 DM 반복은 3시간·1시간·30분·10분·15초
- 자동 독촉은 **브라우저 타이머** (대시보드가 열려 있을 때만). 서버 예약은 나중 과제

## 5. 아직 안 된 것 · 시험 안 한 것

- **실제 채널로 처음부터 끝까지 돌려 본 적 없음** (기능별로 총무 DM 에서만 시험)
- 영수증 사진 읽기, 입금 캡처 읽기: 코드만 있음, 실제 사진 미시험 (입금 *문자* 읽기는 시험 완료)
- 정산 DM 실제 발송 미시험 (데모 모드만)
- 환급 받을 계좌 수집 없음 (총무가 직접 보냄)
- DM 답장 읽기·대답(자유 답장 해석), 대화 기억 — 미구현 (`message.im` 이벤트·`im:history` 권한은 준비됨)
- 자동 독촉 서버 예약 — 미구현
- 회식 외 템플릿(MT 등)은 예전 데모 흐름 그대로
